**Files:**

**Interfaces:**
- Consumes: 配置键 `merge_max_messages`、`merge_max_chars`、`merge_ignore_prefixes`、`merge_include_media`
- Produces: `MergeWindowManager(user_key, join_text, start_window, is_window_open, capture, merge_wake, promote_planning, finalize_window, take_planning, rearm_planning, clear_owner, attach_media)`
  - `take_planning(event) -> tuple[Any, str, list[Any], Any] | None`（`(old_event, pending_text, media, pipeline_task)`）
  - `promote_planning(event) -> bool`（置 `event.is_at_or_wake_command = True`）
  - `rearm_planning(event, merged_text, *, pipeline_task=None) -> bool`

**行为契约：**
- 阶段仅 `window` / `planning`；删除 `continuation`、`planning_captures`、`continued_at`、`merge_continuation_ttl`。
- 事件"是否会自己触发 LLM"用 `event.is_at_or_wake_command` 判定（不再用 `is_wake_up()`）。
- `capture()` 仅窗口期有效，且跳过 `is_at_or_wake_command=True` 的事件（唤醒补充由 `merge_wake`/`take_planning` 处理）。
- `promote_planning()`：planning 期 + 非唤醒 + 同用户 + 可合并 + 未超限 → 置 `is_at_or_wake_command=True`，不改 `pending_text`（后续由 `take_planning` + `join_text` 合并）。
- `take_planning()`：planning 期消费状态并 `pop`，返回合并文本（已含窗口期捕获内容）与媒体。
- `rearm_planning()`：为合并重生成的事件重建 planning 状态（`pending_text=merged_text`），支持递归补充。

    optimizer = make_optimizer()
    first = FakeEvent("u1", "group:1", "你可以发一个表情包吗", wake=True)
